# Регрессии Sirus — непроверенный черновик

Новые файлы используют обычное соглашение набора: `require(...)`, встроенный `assert`, возврат тестовой функции. Существующие тесты, вспомогательные файлы и acceptance fixtures не изменялись. Тесты и проектные команды не запускались: синтаксис, исполнение, форматирование и совместимость после интеграции должен проверить ведущий.

## Состав

- `test_world_channel_send.lua`: отправка через GroupSendPolicy → ChatGateway → ChannelIndex; «Мир» у Орды/Альянса, отдельные ID, языки и история «Мир(О)»/«Мир(А)», перенумерация, отсутствие канала, неполные совпадения, нулевой и отключённый ID; пары и тройки GetChannelList, дубликаты ID, язык независимо от фракции и LFG-строк. Строки отправки и существующие ключи бесед не меняются.
- `test_instance_setting_persistence.lua`: существующий `accountState.settings`, явное значение false после миграции, сохранение true/false и других настроек, нормализация строк/чисел/таблицы, повторная миграция без подмены объекта.
- `test_instance_setting_live.lua`: немедленное обновление через SettingsHandler и строгое булево значение.
- `test_instance_chat_lock_and_queue.lua`: независимо от настройки настоящий Chat-lock от API/события не позволяет отправку, очередь остаётся в истории без автоматической отправки после смены настройки и снятия ограничения.
- `test_instance_policy_lifecycle.lua`: false/nil/true × М+/БГ/арена; реальный SuspendController, видимость, notice, `_wmSuspended`, снятие ограничения после выключения и выхода.
- `test_instance_policy_send.lua`: реальные HandleSend и транспортный вызов, true блокирует, false/nil разрешают, выключение снимает устаревшую блокировку отправки и статус. Входные content-пробы намеренно продолжают сообщать активность: проверяется защита границы отправки от устаревшего аддонного состояния.
- `test_transcript_open_and_width.lua`: первый показ, повторное открытие и новое сообщение при скрытом окне без прокрутки, позднее появление реальной ширины, повторная раскладка и изменение только ширины при неизменной высоте. В FakeUI отложенную раскладку явно вызывает OnUpdate.
- `test_transcript_resize_anchor.lua`: сохранение сообщения/смещения при перераскладке, сохранение привязки к концу.
- `test_inline_emoji_size.lua`: размер inline-текстур в настоящем пузыре при шрифтах 9/12/17, сохранение переносов, ссылки и исходного текста.
- `ui_rig.lua`: локальное расширение существующего FakeUI, не новый production API.

## Допущения и границы

1. Для М+ используется текущий детектор: `FlavorCompat.hasMythicPlus=true`, instance type `party`, difficulty 8 и событие CHALLENGE_MODE_START. Это моделирует ветку М+, но не доказывает, что Sirus сообщает именно такую сложность. Реальное распознавание Sirus нужно проверить в игре.
2. Пересогласование после смены настройки в lifecycle-тесте вызывается существующим PLAYER_ENTERING_WORLD. Отдельный `test_instance_setting_live.lua` проверяет вызов синхронизации из SettingsHandler; `test_instance_chat_lock_and_queue.lua` проверяет сохранение настоящего Chat-lock при выключении. Их совместное прохождение после подключения ещё не установлено.
3. Тест отправки требует, чтобы false/nil снимали именно аддонные content-блокировки даже при устаревших content-пробах. Проверка реальных серверных ограничений и защищённых API сюда не подменена: эти тесты моделируют отсутствие настоящей серверной блокировки. После интеграции нужно сохранить/проверить существующие тесты настоящего ChatApiLocked.
4. Настройки проверяются после Migrations.Apply, поскольку существующая Schema.NewAccountState сама по себе пока не создаёт settings. Проверка идентичности относится к объекту настроек, не к внутренним массивам сообщений мигратора.
5. FakeUI не рассчитывает привязанные размеры и не переносит строки. ui_rig добавляет только детерминированную оценку высоты FontString по ширине; реальные функции измерения/виртуализации не заменяются. Событие OnSizeChanged вызывается явно по соглашению существующих тестов. Это не визуальная приёмка: размер строк, обрезка и ленивое обновление прямоугольников WoW требуют внутриигровой проверки.
6. Размер эмодзи не привязан к новому API или точному множителю. Выбрано простое наблюдаемое условие: квадратная текстура не меньше текста, растёт вместе с ним, при стандартном шрифте 12 больше прежних 12 пикселей. Это намеренное усиление относительно старого поведения; если художественный контракт иной, ведущему нужно уточнить условие. Реальная область рисунка внутри атласа моками не проверяется.
7. Для пустой истории до прокрутки проверяется наличие показанного пузыря последнего сообщения, а не только текста/диапазона в модели. Тесты не подделывают пользовательский скролл при открытии.

## Приглашение — только проверка чтением

Клик `UI/ConversationPane/AddonBadge.lua` → `onInviteContact` из `UI/ConversationPane/ConversationPane.lua` / `UI/MessengerWindow/MessengerWindow/ConversationWiring.lua` → `Core/Bootstrap/WindowRuntime/WindowCallbacks.lua` → `Core/Bootstrap/InviteHandler.lua` → `SendHandler.HandleSend`. Сейчас `INVITE_TEXT` — английская строка про CurseForge/Wago без ссылки; `Localization.Text(INVITE_TEXT)` не гарантирует русского текста и нужного URL. Код приглашения вне выделенного каталога не менялся. Ведущему нужно подключить русское итоговое сообщение с `https://forum.sirus.su/resources/whisper-messenger-messendzher-dlja-sirus-3-3-5a-df-ui.647`, проверить 255-байтный лимит одиночного шепота или безопасное деление через SendHandler и дополнить тест итоговой отправки при согласовании изменения с `tests/core/test_invite_handler.lua` (старое ожидание равенства `INVITE_TEXT`).

## Что нужно сделать после интеграции

Запустить каждый новый `test_*.lua` штатным Lua 5.1-совместимым раннером проекта, затем полный набор и штатные проверки стиля. Исправлять причины падения, не ослабляя контракт. Устаревшие тесты вне этой папки могут пока ожидать безусловную блокировку в активностях; их согласование — задача интеграции, здесь они не редактировались. Вручную проверить Sirus: первое открытие, скрытие/повторный показ, изменение ширины, история до первого скролла, эмодзи и ссылки, выключение ограничения непосредственно в активности.
